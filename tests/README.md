# close 结案流程回归测试

仅使用 Python 3 标准库，不引入第三方依赖，不修改 `main.py` 的任何功能、数据库格式或错误约定。

## 运行

在项目根目录执行：

```bash
python -m unittest discover -s tests
```

（环境中若无 `python` 命令，可改用 `python3 -m unittest discover -s tests`。）

全部通过时退出码为 0；失败时退出码非零，并指出失败用例。可重复执行。

## 测试范围

- 仅核对 `close`：`create` 只用于准备样例，`show` 只用于读取结案后的工单。
- 每个用例在系统临时目录中使用独立的 SQLite 文件（通过 `--db` 指定），
  用例结束自动清理，不读取或改动默认的 `tickets.sqlite` 等已有数据。
- 每个用例先通过真实命令行入口 `main.py`（子进程）准备两条工单：
  标题“登录失败”/描述“重置密码后仍无法登录”，
  标题“打印异常”/描述“更换网络后无法打印”，初始均为 `open`，编号从创建结果读取。
- 成功用例：对第一条结案，核对退出码 0、标准错误为空、标准输出只有一个
  与 `show` 同结构同字段类型的 JSON 对象（仅 `status` 变为 `closed`）；
  再用另一条 `show` 命令确认 `closed` 已持久化，第二条仍为 `open` 且内容不变。
- 幂等用例：再次结案同一编号仍成功、返回同一工单、不增加工单数量，重新查看结果相同。
- 错误用例：`close abc`、`close 0`、`close -1` 退出码 1、标准输出为空、
  标准错误恰为“工单编号必须为正整数”加行尾换行；`close 999` 退出码 1、
  标准错误恰为“工单不存在”加行尾换行；每次失败后两条工单及数量保持原样。
- 用法错误：`close` 缺编号、追加 `--unknown` 时退出码 2、标准输出为空、
  标准错误包含用法提示（不固定完整文案）。
