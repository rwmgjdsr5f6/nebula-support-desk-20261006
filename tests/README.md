# 回归测试说明

本目录包含命令行工单工具的回归测试，仅使用 Python 3 标准库，
均通过 `python main.py` 的公开命令验证查询结果，不依赖内部函数：

- `test_close.py`：`close` 命令的回归测试。
- `test_history.py`：`history` 命令及结案/重开历史写入规则的回归测试。
- `test_list.py`：`list` 命令的回归测试。
- `test_list_limit.py`：`list --limit` 返回数量控制的回归测试。
- `test_list_has_draft.py`：`list --has-draft` 草稿存在性筛选的回归测试。
- `test_db_open_failure.py`：数据库文件无法打开（父目录不存在、`--db` 指向已存在目录）时退出码 1、标准输出为空、标准错误仅为 `数据库无法打开`，以及参数用法错误优先退出 2 的回归测试。

## 运行

在项目根目录执行：

```bash
python -m unittest discover -s tests
```

全部通过时命令退出码为 0；任何用例失败时退出码非零，并输出失败用例名称与差异详情。

## 覆盖范围

### close（test_close.py）

- 正常结案：退出码 0、标准错误为空、标准输出为与 `show` 同结构的 JSON 对象，仅 `status` 变为 `closed`；结案后 `show` 可读到已保存的 `closed` 状态，另一条工单不受影响。
- 幂等结案：重复 `close` 同一编号仍成功、返回同一工单、工单数量不变。
- 编号格式错误：`close abc` / `close 0` / `close -1` → 退出码 1，标准错误为“工单编号必须为正整数”。
- 编号不存在：`close 999` → 退出码 1，标准错误为“工单不存在”。
- 用法错误：缺少编号或追加未知参数 → 退出码 2，标准错误包含用法提示。

### history（test_history.py）

每个用例在独立临时库中预置两条 open 工单，覆盖：

- 验收主流程：依次 `close`、重复 `close`、`reopen` 后，`history` 仅返回两条记录，
  序号 1 为 `open` → `closed`、序号 2 为 `closed` → `open`，`ticket_id` 均为该工单；
  每项仅含 `event_id`、`ticket_id`、`from_status`、`to_status`，前两项为整数、
  后两项为 `open`/`closed` 字符串；随后 `show` 仍返回原四字段对象且状态为 `open`。
- 新建工单没有历史，返回 `[]`（创建的初始 `open` 不入历史）。
- 重复结案与重复重开不追加记录、不占用序号；`event_id` 在每张工单内独立从 1 递增，
  交错切换后各工单的历史互不混入。
- 跨进程持久化：重新运行后内容与序号不变，后续实际切换继续追加；`history` 为只读，
  重复查询不改动历史表与工单状态。
- 编号解析与 `show` 一致（正号、前导零、首尾空白）；非正整数退出码 1、
- 标准错误为“工单编号必须为正整数”；编号不存在或超过 9223372036854775807 时
  退出码 1、标准错误为“工单不存在”；缺少编号或未知参数退出码 2 并给出用法提示。
  各种失败均不写入历史。
- 旧库兼容：手工构造只有 `tickets`、`ticket_notes` 的旧版本库（含一条过去已结案、
  带备注的工单），启用后历史为 `[]`，重复结案不补记，备注保留；实际 `reopen` 后
  才从序号 1 开始记录（`closed` → `open`）。

### list（test_list.py）

固定样例依次创建三条工单，描述分别为“重置密码后仍无法登录”“更换网络后无法打印”和空字符串，
仅将第二条结案：

| 编号（整数，升序） | 标题 | 描述 | 状态 |
| --- | --- | --- | --- |
| 1 | 登录失败 | 重置密码后仍无法登录 | open |
| 2 | 打印异常 | 更换网络后无法打印 | closed |
| 3 | 导出失败 | （空字符串） | open |

覆盖内容与预期结果：

- 全量列表：`list` 退出码 0、标准错误为空，标准输出只含一个 JSON 数组，
  按整数编号升序包含全部三条工单；每项仅含 `id`、`title`、`description`、`status`，
  `id` 为整数、其余字段为字符串，内容与创建结果一致，状态依次为 `open`、`closed`、`open`。
- 状态筛选：`list --status open` 只返回第一、第三条；`list --status closed`
  只返回第二条；结果仍按编号升序，字段结构与类型不变。
- 空结果：空数据库上的 `list`、`list --status open`、`list --status closed`，
  以及有工单但没有匹配状态（只有 open 工单时筛选 closed），均成功（退出码 0）
  返回 `[]`，标准输出不含任何额外说明文字。
- 参数边界：`--status pending`（非法取值）、只给 `--status` 不提供值、
  追加未知参数 `--unknown`，退出码均为 2，标准输出为空，
  标准错误包含 argparse 的用法提示（不要求匹配其中的路径文字）。
- 只读与可重复性：成功查询与参数错误前后，直接读取 SQLite 核对存量工单的
  数量、编号、标题、描述、状态完全相同；再次调用列表命令返回相同数据。

#### 三条件交集（有数据）

固定样例依次创建编号 1 至 4 的工单，描述均为空字符串：

| 编号 | 标题 | 状态 | 备注 |
| --- | --- | --- | --- |
| 1 | 登录失败 | open | 等待确认、再次等待确认、已复现 |
| 2 | 打印异常 | open | 等待确认 |
| 3 | 登录超时 | closed | 等待确认 |
| 4 | 登录受限 | open | （无备注） |

- `list --status open --keyword 登录 --note-keyword " 等待确认 "` 只返回编号 1：
  编号 3 被状态排除、编号 2 被标题/描述关键字排除、编号 4 被备注条件排除；
  编号 1 的较早备注同样参与匹配，多条备注命中也不会让工单重复出现。
- 仅将状态改为 `closed` 时只返回编号 3；备注关键字改为不存在的文字时返回 `[]`。
- 三条件同时给出时，`--note-keyword` 为空字符串或纯空白退出码 1、标准输出为空、
  标准错误恰为“关键字不能为空”加一个换行；缺少 `--note-keyword` 的值退出码 2、
  标准输出为空、标准错误包含用法提示。
- 正常查询与无匹配查询均退出码 0、标准错误为空，标准输出只有一个 JSON 数组；
  每项保持 `show` 的四字段与类型（`id` 为整数，标题/描述/状态为字符串），
  空字符串描述原样保留，不携带备注或摘要字段。
- 直接读取 SQLite 核对：上述查询前后工单、备注、状态历史三张表均不变，
  同库重复查询返回相同数据。

#### 返回数量限制 --limit（test_list_limit.py）

固定样例依次创建三张描述均为空、状态均为 open 的工单：

| 编号 | 标题 | 备注 |
| --- | --- | --- |
| 1 | 打印异常 | （无备注） |
| 2 | 登录失败 | 已联系用户，等待确认、再次等待确认结果（两条均命中） |
| 3 | 登录超时 | 等待确认 |

因此 `list --status open --keyword 登录 --note-keyword 等待确认` 的匹配集合固定为编号 2、3。覆盖：

- 验收主流程：追加 `--limit 1` 只返回完整的编号 2 工单（四字段结构、类型与原始内容不变）；
  `--limit 5` 与不传 `--limit` 均返回编号 2、3。
- 截取发生在条件交集之后且按编号整数升序：全量列表 `--limit 2` 返回 1、2；
  仅文本或仅备注条件命中 2、3 时 `--limit 1` 返回 2；编号 2 两条备注命中只计一张。
- 数量解析遵循 Python `int()` 规则：`+1`、`01`、前导零、首尾空白（含制表符换行）、
  全角数字均合法；数量超过匹配数时返回全部匹配项不补齐；超过 SQLite 有符号整数上限
  （如 `9223372036854775808`、40 个 9）仍成功返回全部。
- 空结果：无匹配条件、状态全部排除、空库配合有效或超大 `--limit` 均退出 0、输出 `[]`。
- 数量无效：`0`、`-1`、`-0`、`1.5`、`0.0`、`abc`、`1e3`、显式空字符串、纯空白，
  以及 `--limit` 缺少值，均退出 2、标准输出为空、标准错误包含用法提示及 `--limit`。
- 与空关键字同时出现：有效数量配合空/纯空白 `--keyword` 或 `--note-keyword`
  仍退出 1、标准错误恰为“关键字不能为空”加换行；数量无效时优先退出 2。
- 只读与可重复性：成功、空结果及失败查询前后直接读取 SQLite，核对工单、备注、
  状态历史三张表的内容与数量完全不变，重新运行相同查询结果一致。

#### 草稿存在性筛选 --has-draft（test_list_has_draft.py）

固定样例依次创建三张描述均为空的工单，仅将第三张结案：

| 编号 | 标题 | 状态 | 备注 | 草稿 |
| --- | --- | --- | --- | --- |
| 1 | 登录失败 | open | 等待确认 | （无） |
| 2 | 登录超时 | open | 等待确认 | 保存草稿（正文 A） |
| 3 | 打印异常 | closed | （无） | 保存草稿（正文 B，与 A 不同） |

覆盖内容与预期结果：

- 验收主流程：`list --has-draft` 退出码 0、标准错误为空，标准输出只有一个 JSON 数组，
  按整数编号升序只返回编号 2、3；不带该选项的 `list` 仍返回全部三张。
  每项保持 `show` 的四字段与类型（`id` 为整数，标题/描述/状态为字符串），
  内容与同编号 `show` 结果完全一致，不附加草稿正文或额外字段。
- 条件交集与截取顺序：`list --has-draft --status open --keyword 登录
  --note-keyword 等待确认 --limit 1` 只返回编号 2（编号 1 被草稿条件排除、
  编号 3 被状态与关键字排除）；同库 `list --has-draft --after-id 2 --limit 1`
  只返回编号 3，验证条件交集与编号边界先于数量截取。
- 草稿生命周期：覆盖保存第二张草稿后工单不重复出现且草稿整篇替换；
  清除第二张草稿后筛选只剩编号 3，重新保存后恢复编号 2、3，
  跨进程重新调用结果相同。
- 空结果：空库或工单均无草稿时，配合各类其他条件均退出 0、输出 `[]`；
  不带选项的普通列表不受影响。
- 空关键字：带 `--has-draft` 时 `--keyword` 或 `--note-keyword` 显式为空或纯空白
  退出码 1、标准输出为空、标准错误恰为“关键字不能为空”加换行。
- 用法错误：`list --has-draft true`（开关不接收值）与数量为零的 `--limit 0`
  退出码 2、标准输出为空、标准错误包含用法提示；无效数量与空关键字并存时
  argparse 先拒绝数量，仍退出 2。
- 只读与可重复性：成功、空结果及失败查询前后直接读取 SQLite，核对工单、备注、
  状态历史与草稿四张表的内容与数量完全不变，重新运行相同查询结果一致。

## 数据隔离

每个用例使用独立的临时数据库，通过 `--db` 明确指定临时文件位置，
测试结束后自动清理，不使用也不读取工作目录下的默认库 `tickets.sqlite`。
测试比较解析后的 JSON 数据及字段类型，不依赖 JSON 对象的键顺序或格式空格。
`create`、`show`、`close` 的输出、错误结果及 SQLite 存量数据格式保持原样。
