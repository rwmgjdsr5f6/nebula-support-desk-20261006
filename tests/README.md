# 回归测试说明

本目录包含 `close` 命令（`test_close.py`）与 `list` 命令（`test_list.py`）的回归测试，仅使用 Python 3 标准库，通过真实命令行入口 `python main.py` 验证查询结果，不直接调用内部函数。

## 运行

在项目根目录执行：

```bash
python -m unittest discover -s tests
```

全部通过时命令退出码为 0；任何用例失败时退出码非零，并输出失败用例名称与差异详情。

## 覆盖范围

### test_close.py（结案）

- 正常结案：退出码 0、标准错误为空、标准输出为与 `show` 同结构的 JSON 对象，仅 `status` 变为 `closed`；结案后 `show` 可读到已保存的 `closed` 状态，另一条工单不受影响。
- 幂等结案：重复 `close` 同一编号仍成功、返回同一工单、工单数量不变。
- 编号格式错误：`close abc` / `close 0` / `close -1` → 退出码 1，标准错误为“工单编号必须为正整数”。
- 编号不存在：`close 999` → 退出码 1，标准错误为“工单不存在”。
- 用法错误：缺少编号或追加未知参数 → 退出码 2，标准错误包含用法提示。

每个用例在独立临时数据库中准备两条合成工单（标题“登录失败”“打印异常”），
通过 `--db` 指向临时文件，结束后自动清理，不读取或改动用户已有数据库。

### test_list.py（列表查询）

每个用例在独立临时数据库中依次创建三条工单，再仅将第二条结案：

| 编号 | 标题 | 描述 | 状态 |
| --- | --- | --- | --- |
| 第一条 | 登录失败 | 重置密码后仍无法登录 | open |
| 第二条 | 打印异常 | 更换网络后无法打印 | closed |
| 第三条 | 导出失败 | （空字符串） | open |

- 列出全部：`list` → 退出码 0、标准错误为空；标准输出只含一个 JSON 数组，按整数编号升序包含三条工单。每项仅含 `id`、`title`、`description`、`status` 四个字段，`id` 为整数、其余为字符串，内容对应创建结果，状态依次为 `open`、`closed`、`open`（第三条描述为空字符串）。
- 按状态筛选：`list --status open` 只返回第一、第三条；`list --status closed` 只返回第二条；结果均保持编号升序，退出码 0 且标准错误为空。
- 空库与无匹配：空数据库执行 `list`、`list --status open`、`list --status closed`，以及在只有 `open` 工单的库中筛选 `closed`，均成功返回 `[]`，标准错误为空，JSON 之后没有任何额外说明文字。
- 参数边界：`--status pending`（非法取值）、只给 `--status` 不带值、追加未知参数 `--unknown` → 退出码 2，标准输出为空，标准错误包含 argparse 用法提示（不校验其中的路径文字）。
- 只读与可重复性：成功查询与参数错误前后，已有工单的数量、编号、标题、描述和状态完全相同；再次调用列表命令返回相同数据。

所有用例通过 `--db` 显式指定临时目录下的数据库文件，结束后自动清理，不使用也不生成工作目录下的默认库 `tickets.sqlite`。断言比较的是 `json.loads` 解析后的数据及字段类型，不依赖 JSON 对象的键序或格式空格；并通过整段输出解析确认标准输出中除一个 JSON 值外没有其他文字。
