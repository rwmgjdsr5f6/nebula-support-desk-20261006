# 回归测试说明

本目录包含命令行工单工具的回归测试，仅使用 Python 3 标准库，
均通过 `python main.py` 的公开命令验证查询结果，不依赖内部函数：

- `test_close.py`：`close` 命令的回归测试。
- `test_list.py`：`list` 命令的回归测试。

## 运行

在项目根目录执行：

```bash
python -m unittest discover -s tests
```

全部通过时命令退出码为 0；任何用例失败时退出码非零，并输出失败用例名称与差异详情。

## 覆盖范围

### close（test_close.py）

- 正常结案：退出码 0、标准错误为空、标准输出为与 `show` 同结构的 JSON 对象，仅 `status` 变为 `closed`；结案后 `show` 可读到已保存的 `closed` 状态，另一条工单不受影响。
- 幂等结案：重复 `close` 同一编号仍成功、返回同一工单、工单数量不变。
- 编号格式错误：`close abc` / `close 0` / `close -1` → 退出码 1，标准错误为“工单编号必须为正整数”。
- 编号不存在：`close 999` → 退出码 1，标准错误为“工单不存在”。
- 用法错误：缺少编号或追加未知参数 → 退出码 2，标准错误包含用法提示。

### list（test_list.py）

固定样例依次创建三条工单，描述分别为“重置密码后仍无法登录”“更换网络后无法打印”和空字符串，
仅将第二条结案：

| 编号（整数，升序） | 标题 | 描述 | 状态 |
| --- | --- | --- | --- |
| 1 | 登录失败 | 重置密码后仍无法登录 | open |
| 2 | 打印异常 | 更换网络后无法打印 | closed |
| 3 | 导出失败 | （空字符串） | open |

覆盖内容与预期结果：

- 全量列表：`list` 退出码 0、标准错误为空，标准输出只含一个 JSON 数组，
  按整数编号升序包含全部三条工单；每项仅含 `id`、`title`、`description`、`status`，
  `id` 为整数、其余字段为字符串，内容与创建结果一致，状态依次为 `open`、`closed`、`open`。
- 状态筛选：`list --status open` 只返回第一、第三条；`list --status closed`
  只返回第二条；结果仍按编号升序，字段结构与类型不变。
- 空结果：空数据库上的 `list`、`list --status open`、`list --status closed`，
  以及有工单但没有匹配状态（只有 open 工单时筛选 closed），均成功（退出码 0）
  返回 `[]`，标准输出不含任何额外说明文字。
- 参数边界：`--status pending`（非法取值）、只给 `--status` 不提供值、
  追加未知参数 `--unknown`，退出码均为 2，标准输出为空，
  标准错误包含 argparse 的用法提示（不要求匹配其中的路径文字）。
- 只读与可重复性：成功查询与参数错误前后，直接读取 SQLite 核对存量工单的
  数量、编号、标题、描述、状态完全相同；再次调用列表命令返回相同数据。

## 数据隔离

每个用例使用独立的临时数据库，通过 `--db` 明确指定临时文件位置，
测试结束后自动清理，不使用也不读取工作目录下的默认库 `tickets.sqlite`。
测试比较解析后的 JSON 数据及字段类型，不依赖 JSON 对象的键顺序或格式空格。
`create`、`show`、`close` 的输出、错误结果及 SQLite 存量数据格式保持原样。
