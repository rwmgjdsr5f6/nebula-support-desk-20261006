# 本地客服工单中心

管理客户工单的本地单机命令行工具，采用 Python 3 标准库与 SQLite，无需安装第三方依赖，也不提供任何联网功能。

当前版本支持最小流程：**创建工单**、**按编号查看工单**、**按编号结案**、**按编号重新打开**、**工单内部备注**、**状态变更历史**与**列表筛选**（暂不支持分派、回复）。

## 环境要求

- Python 3（仅使用标准库）

## 用法

入口为项目根目录下的 `main.py`：

```bash
python main.py [--db 数据库文件] <命令> [参数]
```

### 数据库位置

- 全局选项 `--db` 指定 SQLite 数据库文件路径，例如 `--db demo.sqlite`。
- 未提供 `--db` 时，默认使用**当前工作目录**下的 `tickets.sqlite`。
- 数据库文件尚不存在时会自动创建（要求其父目录已存在且可读写）；已存在则继续使用，重新运行或再次创建工单都不会清空已有记录。
- 不同 `--db` 文件中的数据彼此独立。

### 创建工单

```bash
python main.py --db demo.sqlite create --title "登录失败" --description "重置密码后仍无法登录"
```

- `--title`：工单标题。去除首尾空白后为空则拒绝创建；有效标题去除首尾空白后保存。
- `--description`：工单描述，按原文保存，允许空字符串。
- 创建成功后，工单获得该数据库中唯一的正整数编号（新数据库首条编号为 1，编号在重新运行后保持稳定），初始状态固定为 `open`。
- 成功时退出码为 0，标准输出只包含一个 JSON 对象，字段为 `id`、`title`、`description`、`status`（`id` 为整数，其余为字符串），中文可直接阅读：

```json
{"id": 1, "title": "登录失败", "description": "重置密码后仍无法登录", "status": "open"}
```

### 查看工单

```bash
python main.py --db demo.sqlite show 1
```

- `show` 后接工单编号，返回对应工单，不改变任何数据。
- 成功时退出码为 0，标准输出为包含 `id`、`title`、`description`、`status` 四个字段的 JSON 对象，内容与创建时一致。

### 结案工单

```bash
python main.py --db demo.sqlite close 1
```

- `close` 后接工单编号，仅将该工单状态由 `open` 改为 `closed`，编号、标题和描述保持原值，其他工单不受影响。
- 对已经是 `closed` 的工单再次结案同样成功，返回相同工单及 `closed` 状态，不新增记录或改变编号。
- 实际发生 `open` → `closed` 切换时，会在该工单的状态变更历史中追加一条记录；重复结案不追加、不占用历史序号（详见“状态变更历史”）。
- 成功时退出码为 0，标准输出只包含一个 JSON 对象，字段与类型和查看工单一致，中文可直接阅读：

```json
{"id": 1, "title": "登录失败", "description": "重置密码后仍无法登录", "status": "closed"}
```

### 重新打开工单

```bash
python main.py --db demo.sqlite reopen 1
```

- `reopen` 后接工单编号，仅将状态由 `closed` 改回 `open`，编号、标题、描述与已有备注均保持不变，其他工单不受影响。
- 对已经是 `open` 的工单再次重开同样成功，输出结构与查看工单一致。
- 实际发生 `closed` → `open` 切换时，会在该工单的状态变更历史中追加一条记录；重复重开不追加、不占用历史序号（详见“状态变更历史”）。

### 状态变更历史

```bash
python main.py --db demo.sqlite history 1
```

- `history <编号>`：读取指定工单的全部状态切换记录，按 `event_id` 升序组成一个 JSON 数组。
  - 编号解析与查找规则与 `show` 完全一致（允许正号、前导零与首尾空白）。
  - 仅在结案或重开导致状态**实际变化**时追加历史：`close` 把 `open` 改为 `closed` 记一条，`reopen` 把 `closed` 改为 `open` 记一条。
  - 重复结案或重复重开仍成功返回当前工单，但既不写入历史也不占用序号。
  - 创建只产生初始 `open` 状态，**不**记入历史；工单存在但没有历史时输出 `[]`。
  - 旧版本数据库中原有的工单，其过去的状态过程不作推断，历史从启用本功能后的**实际切换**开始记录。
  - `event_id` 在**每张工单内**从 1 开始独立递增（不同工单各自计数）；`ticket_id` 为实际工单编号，查询结果不会混入其他工单的记录。
  - 历史保存在同一个 SQLite 文件中（`ticket_history` 表），重新运行后内容与序号不变，后续实际切换继续追加；已有 SQLite 文件继续使用，启用时自动补建历史表，原工单与备注保留。
  - 成功时退出码为 0，标准错误为空，标准输出仅为一个 JSON 数组，每项仅含 `event_id`、`ticket_id`、`from_status`、`to_status` 四个字段，前两项为整数、后两项为 `open` 或 `closed` 字符串，中文不涉及：

```json
[{"event_id": 1, "ticket_id": 1, "from_status": "open", "to_status": "closed"}, {"event_id": 2, "ticket_id": 1, "from_status": "closed", "to_status": "open"}]
```

- 该操作为只读，不改变工单、备注或已有历史；例如依次 `close 1`、`close 1`、`reopen 1` 后查询 `history 1`，只返回序号 1（`open` → `closed`）与序号 2（`closed` → `open`）两项，此时 `show 1` 仍返回原四字段对象且状态为 `open`。

### 工单内部备注

```bash
python main.py --db demo.sqlite add-note 1 --text "已复现"
python main.py --db demo.sqlite notes 1
python main.py --db demo.sqlite notes 1 --keyword "等待"
```

- `add-note <编号> --text <内容>`：为指定工单追加一条本地内部备注，不改变工单本身。
  - 编号解析与查找规则与 `show` 完全一致（允许正号、前导零与首尾空白）。
  - `--text` 的有效内容**按原文保存**，首尾空白、换行、引号等字符一律保留；仅当内容为空字符串或去除首尾空白后为空时拒绝。
  - 相同内容重复提交仍会各自追加为独立备注，不去重。
  - `note_id` 在**每张工单内**从 1 开始独立递增（不同工单各自计数）；`ticket_id` 为实际工单编号。
  - 成功时退出码为 0，标准错误为空，标准输出只含一个 JSON 对象，仅含 `note_id`、`ticket_id`、`text` 三个字段，前两项为整数、`text` 为字符串，中文可直接阅读：

```json
{"note_id": 1, "ticket_id": 1, "text": "已复现"}
```

- `notes <编号> [--keyword 关键字]`：读取指定工单的内部备注，按 `note_id` 升序组成一个 JSON 数组，每项结构与追加成功时的对象一致；工单存在但没有备注（或没有命中）时输出 `[]`。该操作为只读，不新增或修改任何记录。
  - 不传 `--keyword` 时返回该工单的全部备注。
  - 传入 `--keyword` 时，关键字先去除首尾空白，再对备注正文做**区分大小写的连续字面子串匹配**；关键字中的内部空白、`%`、`_`、引号与反斜杠均按原字符比较，不作为通配符或正则，中文直接参与匹配。命中的备注保留原 `note_id` 与完整原文，不附加匹配标记；相同内容的多条备注各自保留，其他工单的备注不参与查询。
  - 工单存在后才校验关键字：显式空字符串或去除首尾空白后为空时，退出码 1，标准错误仅输出 `关键字不能为空` 及换行，标准输出为空。
- 备注与工单状态无关：`open` 与 `closed` 工单都可以追加和读取，结案或重开后备注继续保留；不同工单的备注互不影响。
- 备注保存在同一个 SQLite 文件中，重新运行后编号与内容不变；已有的数据库文件无需重建，原有工单初始没有备注（`notes` 返回 `[]`）。

### 列出工单

```bash
python main.py --db demo.sqlite list [--status open|closed] [--keyword 关键字] [--note-keyword 备注关键字] [--limit 数量]
```

- 不带任何参数时返回库中全部工单，按编号（整数）升序排列。
- `--status`：按状态筛选，仅接受 `open` 或 `closed`；不传则不按状态筛选。
- `--keyword`：可选的关键字查询。关键字会先去除首尾空白，再做**区分大小写的连续字面子串匹配**；标题或问题描述任一处包含该关键字即入选，两处同时命中也只返回一次。
  - 关键字中的内部空白、`%`、`_`、引号与反斜杠均按原字符比较，不会被解释成通配符、正则表达式或多个搜索词；中文直接参与匹配。
  - `--keyword` 只搜索标题与问题描述，不搜索内部备注。
- `--note-keyword`：可选的备注关键字查询。关键字同样先去除首尾空白，再对每条内部备注正文做**区分大小写的连续字面子串匹配**（特殊字符规则与 `--keyword` 一致）；工单只要有任意一条备注命中即入选，较早的备注也参与匹配，多条备注同时命中仍只返回一次，没有备注的工单不入选。
  - `--note-keyword` 与 `--status`、`--keyword` 同时给出时取交集：备注命中、标题/描述命中与状态条件必须同时满足。
- `--limit`：可选的返回数量。提供时先按上述全部条件取交集、按工单编号整数升序排列，再只返回编号最小的前指定数量张工单；不提供时返回全部匹配工单。
  - 数量按 Python `int()` 规则解析：允许正号、前导零与首尾空白（如 `+1`、`01`、`  2  `），解析结果为正整数即有效；数量超过匹配工单数时返回全部匹配项，不补齐空位，即使数量超过 SQLite 有符号整数上限（9223372036854775807）也按此语义成功处理。
  - 数量为零、负数、小数（如 `1.5`）、不能解析的文本或显式空字符串时，退出码 2，标准输出为空，标准错误给出包含 `--limit` 的用法提示。
- 成功时退出码为 0，标准错误为空，标准输出只有一个 JSON 数组，每项的字段与类型和查看工单一致，按编号升序排列，不附加备注内容、匹配标记、总数或分页信息；没有匹配项、库中没有工单或条件排除了全部命中时，输出 `[]`。
- 查询为只读操作，不修改已有工单、备注与状态历史，不新增占位记录；默认数据库位置与 `--db` 选择规则不变，已有数据库无需重建即可查询。

```bash
python main.py --db demo.sqlite list --keyword " 登录 "
python main.py --db demo.sqlite list --keyword 登录 --status closed
python main.py --db demo.sqlite list --note-keyword " 等待确认 "
python main.py --db demo.sqlite list --note-keyword 等待确认 --status closed
python main.py --db demo.sqlite list --status open --keyword 登录 --note-keyword 等待确认 --limit 1
```

## 错误结果

以下情况退出码均为 1，且标准输出为空，错误信息输出到标准错误：

| 情况 | 标准错误输出 |
| --- | --- |
| 创建时标题去除首尾空白后为空 | `标题不能为空` |
| `show` 的编号不是正整数（如 `abc`、`0`、`-1`） | `工单编号必须为正整数` |
| 编号为正整数但工单不存在（如 `show 999`） | `工单不存在` |
| `close` 的编号不是正整数（如 `abc`、`0`、`-1`） | `工单编号必须为正整数` |
| 编号为正整数但工单不存在（如 `close 999`） | `工单不存在` |
| `reopen` 的编号不是正整数（如 `abc`、`0`、`-1`） | `工单编号必须为正整数` |
| 编号为正整数但工单不存在（如 `reopen 999`） | `工单不存在` |
| `history` 的编号不是正整数（如 `abc`、`0`、`-1`） | `工单编号必须为正整数` |
| 编号为正整数但工单不存在（如 `history 999`） | `工单不存在` |
| `add-note` / `notes` 的编号不是正整数（如 `abc`、`0`、`-1`） | `工单编号必须为正整数` |
| 编号为正整数但工单不存在（如 `add-note 999 --text x`） | `工单不存在` |
| `add-note` 的内容为空字符串或去除首尾空白后为空 | `备注不能为空` |
| `notes --keyword` 显式传入空字符串或去除首尾空白后为空 | `关键字不能为空` |
| `list --keyword` 显式传入空字符串或去除首尾空白后为空 | `关键字不能为空` |
| `list --note-keyword` 显式传入空字符串或去除首尾空白后为空 | `关键字不能为空` |

空白标题被拒绝、编号校验失败、关键字为空、备注内容为空或工单不存在时，均不会改变库中已有工单与备注的数据（不存在的数据库按既有规则自动创建，但不会生成占位工单或备注）。`close` 缺少编号或带有未识别参数时，退出码为 2，标准输出为空，标准错误给出用法提示。`add-note` 缺少编号、缺少 `--text` 或其值、带有未识别参数，以及 `notes`、`history` 缺少编号或带有未识别参数时，同样退出码为 2、标准输出为空、标准错误给出用法提示；`notes --keyword` 缺少参数值时亦然。`list` 中 `--keyword` 或 `--note-keyword` 缺少参数值、`--status` 取值不是 `open`/`closed`、`--limit` 缺少参数值或其值不是有效正整数（零、负数、小数、不能解析的文本、显式空字符串）或出现未知选项时，同样退出码为 2、标准输出为空、标准错误给出用法提示。有效的 `--limit` 与空关键字同时出现时仍按关键字为空处理（退出码 1）；数量本身无效时优先返回退出码 2 的用法错误。

编号按 Python `int()` 规则解析（允许正号、前导零与首尾空白）。对于能解析为正整数、但大于 SQLite 可保存的最大整数 9223372036854775807 的编号（如 `9223372036854775808`，带正号、前导零或空白的写法同理），`show`、`close`、`reopen`、`history` 一律按工单不存在处理：退出码 1，标准输出为空，标准错误仅输出 `工单不存在` 及换行，不创建占位工单、不改动已有工单与历史。最大整数本身是合法编号，库中无对应记录时同样返回 `工单不存在`。
